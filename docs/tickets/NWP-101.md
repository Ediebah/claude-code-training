## Description

Ops exports the payments table several times a day: merchant queries, month-end reconciliation, and anything Finance asks for. The export works, but it is fixed. Every column, current filter only, no say in what comes out.

The card last-four is in every file, so anything we send to a merchant has to be cleaned up by hand first. Dana's team estimates 3–4 hours a month of manual spreadsheet editing, and a near-miss last quarter where an unedited file nearly went to the wrong merchant.

Add an options dialog to the existing Export button on `/payments`.

## Acceptance criteria

- [ ] Ops can choose which columns are included. Card last-four is **off** by default.
- [ ] Ops can choose scope: **current filter** or **all payments**. Current filter is the default, and the row count is visible before download.
- [ ] The filename reflects the scope and the date, for example `payments-disputed-2026-08-13.csv`.
- [ ] Amounts stay in minor units internally and are formatted once on the way out, with currency in its own column.
- [ ] Deselecting every column disables Download rather than producing an empty file.

## Notes from the team

- Column names arrive from the client, so **validate them server-side**. Do not interpolate them into SQL.
- The payments table is paginated. Building this in the browser exports the current page only, which is the bug we would be shipping instead of the feature.
- There is already a query builder behind `GET /api/payments`. Reuse it rather than writing a second one.
